# Defensive decoy-404 review fixes (v2)

Second-pass review of commit `be564c0`, which addresses the four issues raised in v1. The gzip bomb payload is now precomputed once at import, `/admin` was removed from the top-level route exemption list, and `decoy_404_middleware` gained an injectable `rng` that the end-to-end tests thread through so both decoy branches run through the real production entrypoint. All four prior issues are resolved and no new concerns were introduced.

Watch for: nothing blocking. The one residual observation is informational — the forced-bomb e2e case verifies bomb bytes by building a fresh `build_decoy_response` rather than reading them off the wire, but the branch selection itself now goes through `decoy_404_middleware` (confirmed), so the coverage gap from v1 is closed.

**Verdict**: APPROVED

## High-level view

The gzip bomb is now a module-level constant (`_BOMB_COMPRESSED_BYTES`) compressed once at import; `_build_gzip_bomb_response` hands back that constant, so the per-request 50 MiB allocation and DEFLATE pass are gone. This directly removes the server-side amplification v1 flagged.

The `/admin` entry is gone from `_KNOWN_TOP_LEVEL_ROUTES`, and a comment documents why (admin lives under `/events/.../api/admin/`, already covered by the `/events/` exemption). The unit tests now assert `/admin` and `/admin/users` are *not* exempt, locking the corrected behavior in.

`decoy_404_middleware` now accepts an optional `rng` and threads it to `build_decoy_response`. The test `_build_app` always calls the real `decoy_404_middleware` (passing the forced `rng` through), rather than re-implementing the middleware body, so the forced-plain and forced-bomb cases now exercise the production path end-to-end — closing both the "e2e bypasses the middleware" and "bomb branch never hits production entrypoint" gaps.

### Gzip bomb precomputation

`_BOMB_COMPRESSED_BYTES = gzip.compress(b"\0" * BOMB_DECOMPRESSED_SIZE)` runs once at module load, and `_build_gzip_bomb_response` returns a `Response` wrapping that constant. The 50 MiB source buffer and the DEFLATE pass no longer occur per request, so a hostile scanning burst can no longer amplify into repeated server-side memory and CPU cost. Content-Length is still left for Starlette to derive from the actual compressed bytes, so the wire framing stays consistent.

### `/admin` exemption removed

`_KNOWN_TOP_LEVEL_ROUTES` now lists only `/login`, `/logout`, `/register`, `/lost-rockets`, `/static` — all real top-level routes. The `test_is_exempt_path_false` table now includes `/admin` and `/admin/users`, so an anonymous probe to either receives the decoy rather than an honest 404, and a regression that re-adds the exemption would fail the test.

### RNG threaded through the real entrypoint

`decoy_404_middleware(request, call_next, rng=None)` passes `rng` to `build_decoy_response`, and production `main.py` omits it (real randomness). In the tests, `_build_app`'s inner `_decoy` middleware now calls `decoy_404_middleware(request, call_next, rng=rng)` directly instead of re-implementing the status/user/exempt checks. A regression inside `decoy_404_middleware` (inverting the user check, dropping the exempt check) would now be caught by the forced-branch e2e cases, which was not true in v1.

The forced-bomb test still decompresses bytes obtained from a freshly built `build_decoy_response(rng=_ForceBomb())` rather than from the client response, because httpx auto-decodes gzip and reading the raw wire bytes through the client is awkward. The branch *selection* is what now runs through the production middleware, which is the coverage that mattered.
